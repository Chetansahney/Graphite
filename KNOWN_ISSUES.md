### 🔴 New Issue: `DuplicateSelectedLayers` uses root network path instead of current sub-graph path

**Location:** `editor/src/messages/portfolio/document/document_message_handler.rs` line 430

**Reproducer:**
1. Open the node graph for any layer (enter a sub-graph via double-click).
2. Select a node inside the sub-graph.
3. Press **Ctrl+D** to duplicate.

**What happens:** The duplication operates on the root network (`&[]`) instead of the currently-active sub-graph (`&self.selection_network_path`). This causes the parent layer to be moved/duplicated into the wrong location — placing it inside itself or at the root when it should stay in the sub-graph.

**Root cause in code:**
```rust
// Line 430 — WRONG: uses &[] (root) instead of &self.selection_network_path
let mut layers = self.network_interface.shallowest_unique_layers(&[]).collect::<Vec<_>>();
```
The same hardcoded `&[]` path is also used on lines 448 (`upstream_flow_back_from_nodes`) and 456 (`copy_nodes`), so the entire copy+paste operation is scoped to the root network even when the user is inside a nested network.

**Relates to:** [upstream #3809](https://github.com/GraphiteEditor/Graphite/issues/3809) — *Ctrl+D inside a layer's sub-graph causes the parent layer to be placed inside it* (`Good First Issue`)

### 💥 New Issue: Export dialog can panic when multiple files are open (confirmed crash path)

**Location:** `editor/src/messages/layout/layout_message_handler.rs` line 349 and `editor/src/messages/dialog/dialog_message_handler.rs` lines 86–113

**Reproducer (matches stack trace from [#3932](https://github.com/GraphiteEditor/Graphite/issues/3932)):**
1. Open 3 documents, all with artboards.
2. Copy a path from one document.
3. Switch to another document, open the Export dialog.
4. Trigger export — crash.

**Root cause in code:** The export dialog's `artboards: HashMap<LayerNodeIdentifier, String>` is populated **only when `RequestExportDialog` is dispatched** (line 104). If you switch active documents without reopening the dialog, the artboard keys become stale (they belong to a different document). When a widget callback from the old artboard list fires:
```rust
// layout_message_handler.rs:349 — panics if final_entry is None
(final_entry.unwrap().on_commit.callback)(&())
```
The `find()` loop on the old value-path returns `None`, and `unwrap()` panics.

Additionally, line 118 in `export_dialog_message_handler.rs`:
```rust
.on_update(|number_input: &NumberInput| ExportDialogMessage::ScaleFactor { factor: number_input.value.unwrap() }.into())
```
will also panic if the `NumberInput` value is `None` (e.g. when the user clears the field).

### ⚠️ New Issue: Resizing a layer to zero-size causes permanent breakage

**Location:** `editor/src/messages/portfolio/document/document_message_handler.rs` line 2130

**Reproducer:**
1. Draw any rectangle or shape.
2. Drag one resize handle all the way to the opposite edge (collapsing the shape to zero size).
3. Try to resize it back.

**What happens:** The shape cannot be scaled back up because the resize math divides by the size vector. The code acknowledges this:
```rust
// TODO: This is a hacky band-aid. It still results in the shape becoming zero-sized. Properly fix this using the correct math.
let size = size.max(DVec2::ONE);
```
The clamp prevents a divide-by-zero crash, but the shape is already stuck at zero size before the clamp applies.

### ⚠️ New Issue: "Normal to Paths" and "Tangent to Paths" snapping broken for curves; also requires "Intersections of Paths" to be enabled

**Location:** `editor/src/messages/portfolio/document/utility_types/misc.rs` lines 457–469

**Reproducer:**
1. Draw a curved Bezier path.
2. Enable **Snap to → Normal to Paths** or **Snap to → Tangent to Paths**.
3. Drag another object near the curve.

**What happens:** Normal/Tangent snapping only works on straight line segments. On curved segments it uses the chord direction (start-to-end of the curve) rather than the true curve normal/tangent at the closest point. Additionally, both snap modes require the unrelated **"Intersections of Paths"** option to also be enabled, which is an acknowledged dependency bug. These issues are documented with TODO comments in the code:
```rust
// TODO: This works correctly for line segments, but not curved segments.
// TODO: Fix the bug/limitation that requires 'Intersections of Paths' to be enabled
```

### ⚠️ New Issue: Shape Tool creates parametric nodes — Path Tool cannot edit their handles

**Location:** `editor/src/messages/tool/tool_messages/shape_tool.rs` lines 924–937

**Reproducer:**
1. Use the **Shape Tool** to draw any polygon, star, circle, arc, or spiral.
2. Switch to the **Path Tool** and try to drag a Bezier handle.

**What happens:** Shapes created by the Shape Tool are built from **parametric node graphs** (e.g. `Polygon::create_node()`, `Circle::create_node()`, etc.) rather than raw `VectorData` subpaths. The Path Tool's handle editor only works on layers that contain direct vector path data. There is no conversion step, so handles cannot be dragged on Shape Tool shapes.

**Relates to:** [upstream #3891](https://github.com/GraphiteEditor/Graphite/issues/3891) — *Handle operations don't work on shapes created with the Shape Tool*
